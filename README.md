# Клуб Коко

Портал для членов клуба: профили, каталог людей с поиском по виду деятельности,
статусы «готов общаться / занят / не беспокоить», личные сообщения.
Плюс кабинет персонала: выдача клубных NFC-карт, отметка входа, «кто сейчас в клубе».

Бар клуба (заказы, оплата, кухня) работает в «Падаче» на тарифе «Стойка».
Клубная карта продаётся там обычной позицией за 1 500 ₽, а привязывается здесь.
Общий ключ между системами — номер телефона. Пункт «Меню» в портале ведёт на страницу
заведения в Падаче — адрес задаётся `MENU_URL` в `.env`.

## Стек

Django 5 + DRF + SimpleJWT, PostgreSQL; React 18 + Vite + TypeScript.

- `backend/members` — участник (он же учётная запись), анкета, вход по SMS-коду
- `backend/club` — клубные карты, визиты, кабинет персонала
- `backend/chat` — личные переписки (пока без онлайна: новое видно при обновлении)
- `frontend/src/pages` — портал; `frontend/src/pages/staff` — экраны персонала

## Как гость становится членом клуба

1. На стойке QR-код на портал. Гость входит по номеру телефона (SMS-код) и заполняет анкету
   с согласием на обработку персональных данных.
2. Бариста пробивает в Падаче «Клубная карта — 1 500 ₽».
3. «Персонал → Гости и карты»: найти гостя по телефону, «Выдать карту», приложить карту к ридеру.
4. Гость появляется в каталоге и может писать другим участникам.

Гостя без смартфона бариста заводит сам («+ Новый гость»). Потерянная карта —
«Перевыпустить»: старая перестаёт работать, профиль и переписки остаются.

## NFC

Карты — NTAG213-совместимые, 7-байтный UID (например, `53:FB:51:19:23:00:01`).
Идентификатор карты — заводской серийный номер, на карту ничего не пишется.
В базе хранится как `53FB5119230001`.

Ридер: USB, 13,56 МГц, **режим эмуляции клавиатуры, вывод UID в HEX, поддержка 7-байтного UID**.
Он «печатает» номер и Enter; экраны персонала ловят это сами (`useCardReader.ts`), фокус не нужен.

- «Экран у входа» (`/staff/entrance`) — планшет с ридером у двери: приложил — вошёл, ещё раз — вышел.
- «Кто в клубе» (`/staff`) — планшет на баре; ридер сюда тоже можно подключить.
- Кто забыл приложить карту на выходе, перестаёт числиться в клубе в `CLUB_DAY_START_HOUR` (6:00).

## Запуск

```bash
cp .env.example .env
docker compose up
docker compose exec backend python manage.py createsuperuser   # персонал: телефон + пароль
docker compose exec backend python manage.py demo_members      # тестовые участники и учётка персонала (только для разработки)
```

Портал — http://localhost:5180, вход персонала — http://localhost:5180/staff/login,
админка — http://localhost:5180/admin/. Код из SMS в разработке пишется в лог бэкенда.

Без Docker (SQLite):

```bash
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
DB_ENGINE=sqlite .venv/bin/python manage.py migrate
DB_ENGINE=sqlite .venv/bin/python manage.py runserver 8001
cd frontend && npm install && npm run dev
```

Тесты: `DB_ENGINE=sqlite .venv/bin/python manage.py test` из `backend/`.

## Показать сайт по ссылке (GitHub Codespaces)

На GitHub: **Code → Codespaces → Create codespace on main**. Первый запуск — 3–5 минут:
ставятся зависимости, создаётся база SQLite с тестовыми участниками (`.devcontainer/`).
Потом портал откроется сам; адрес вида `https://<имя>-5180.app.github.dev`.

- Чтобы ссылка открывалась у других без входа в GitHub: вкладка **Ports** → порт 5180 →
  правый клик → **Port Visibility → Public**.
- Вход участника — телефон `79000000000`…`79000000005`, код из SMS смотреть в терминале:
  `grep "SMS для" .logs/backend.log | tail -1`.
- Персонал — http://…/staff/login, `79990000001` / `koko-demo-staff`.
- Codespace засыпает через ~30 минут без активности; после пробуждения портал поднимается сам.
  Это демо, не прод: данные тестовые, пароль персонала общий.
