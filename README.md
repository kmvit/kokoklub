# Клуб Коко

Портал для членов клуба: профили, каталог людей с поиском по виду деятельности,
статусы «готов общаться / занят / не беспокоить», личные сообщения.
Плюс кабинет персонала: выдача клубных NFC-карт, отметка входа, «кто сейчас в клубе».

Бар клуба (заказы, оплата, кухня) работает в «Падаче» на тарифе «Стойка».
Клубная карта продаётся там обычной позицией за 1 500 ₽, а привязывается здесь.
Общий ключ между системами — номер телефона. Пункт «Меню» в портале ведёт на страницу
заведения в Падаче — адрес задаётся `MENU_URL` в `.env`.

## Стек

Django 5 + DRF + SimpleJWT, PostgreSQL; React 18 + Vite + TypeScript.

- `backend/members` — участник (он же учётная запись), анкета, вход по почте и паролю
- `backend/club` — клубные карты, визиты, кабинет персонала
- `backend/chat` — личные переписки (пока без онлайна: новое видно при обновлении)
- `frontend/src/pages` — портал; `frontend/src/pages/staff` — экраны персонала

## Как гость становится членом клуба

1. На стойке QR-код на портал. Гость регистрируется с почтой, телефоном и паролем, заполняет анкету
   с согласием на обработку персональных данных.
2. Бариста пробивает в Падаче «Клубная карта — 1 500 ₽».
3. «Персонал → Привязать карту»: найти гостя по телефону или имени, считать метку телефоном
   либо USB-ридером и подтвердить привязку. Кнопка «Выдать карту» в списке гостей ведёт туда же.
4. Гость появляется в каталоге и может писать другим участникам.

Гостя без смартфона бариста заводит сам («+ Новый гость»), после чего открывается страница
привязки карты. Для входа в такую учётную запись администратор позднее задаёт почту и пароль.
Потерянная карта — «Перевыпустить»: старая перестаёт работать, профиль и
переписки остаются. Если метка уже привязана к другому гостю, сервер отклоняет привязку.

## NFC

Карты — NTAG213-совместимые, 7-байтный UID (например, `53:FB:51:19:23:00:01`).
Идентификатор карты — заводской серийный номер, на карту ничего не пишется.
В базе хранится как `53FB5119230001`.

Ридер: USB, 13,56 МГц, **режим эмуляции клавиатуры, вывод UID в HEX, поддержка 7-байтного UID**.
Он «печатает» номер и Enter; экраны персонала ловят это сами (`useCardReader.ts`), фокус не нужен.

- «Экран у входа» (`/staff/entrance`) — планшет с ридером у двери: приложил — вошёл, ещё раз — вышел.
- «Кто в клубе» (`/staff`) — планшет на баре; ридер сюда тоже можно подключить.
- «Гости и карты» (`/staff/guests`) — на телефоне кассира кнопка «Посмотреть гостя по NFC».
  После касания метки открывается карточка гостя с фото, именем, телефоном и состоянием карты.
  Эта проверка не отмечает вход или выход. Сайт должен быть открыт по HTTPS в Chrome на Android,
  NFC на телефоне включён, а метка совместима с NDEF. Доступ к NFC выдаётся браузеру после
  нажатия кнопки. На iPhone и в неподдерживаемых браузерах используйте поиск по имени или
  телефону либо внешний ридер. Перед закупкой партии проверьте реальные метки: телефон должен
  передавать тот же UID, который сохранён при выдаче карты.
- «Привязать карту» (`/staff/bind`) — отдельная страница выдачи метки гостю. После выбора
  гостя кассир считывает UID телефоном или USB-ридером, сверяет его и подтверждает привязку.
- Кто забыл приложить карту на выходе, перестаёт числиться в клубе в `CLUB_DAY_START_HOUR` (6:00).

## Запуск

```bash
cp .env.example .env
docker compose up
docker compose exec backend python manage.py createsuperuser   # телефон, почта и пароль
docker compose exec backend python manage.py demo_members      # тестовые участники и учётка персонала (только для разработки)
```

Портал — http://localhost:5180, единый вход для участников и персонала — http://localhost:5180/login,
админка — http://localhost:5180/admin/ (та же почта и пароль).

Без Docker (SQLite):

```bash
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
DB_ENGINE=sqlite .venv/bin/python manage.py migrate
DB_ENGINE=sqlite .venv/bin/python manage.py runserver 8001
cd frontend && npm install && npm run dev
```

Тесты: `DB_ENGINE=sqlite .venv/bin/python manage.py test` из `backend/`.

## Показать сайт по ссылке (GitHub Codespaces)

На GitHub: **Code → Codespaces → Create codespace on main**. Первый запуск — 3–5 минут:
ставятся зависимости, создаётся база SQLite с тестовыми участниками (`.devcontainer/`).
Потом портал откроется сам; адрес вида `https://<имя>-5180.app.github.dev`.

- Чтобы ссылка открывалась у других без входа в GitHub: вкладка **Ports** → порт 5180 →
  правый клик → **Port Visibility → Public**.
- Тестовые участники `79000000000`…`79000000005` созданы без доступа к входу.
- Персонал — http://…/login, `staff-demo@example.com` / `koko-demo-staff` (только локально).
- Codespace засыпает через ~30 минут без активности; после пробуждения портал поднимается сам.
  Это демо, не прод: данные тестовые, пароль персонала общий.

## Первый администратор на Vercel

В Production окружении Vercel добавьте `BOOTSTRAP_ADMIN_EMAIL` (ваша почта), `BOOTSTRAP_ADMIN_PHONE` (ваш мобильный номер)
и `BOOTSTRAP_ADMIN_PASSWORD` (новый длинный пароль) в **Project → Settings → Environment Variables**.
Затем сделайте **Deployments → Redeploy** последнего Production deployment. При сборке
`vercel.json` выполнит миграции и `bootstrap_admin`: он создаст администратора, если
этого номера ещё нет в базе. Повторные сборки не меняют его пароль и права. После успешного
входа удалите эти переменные и снова разверните сайт, чтобы пароль больше не оставался
в окружении проекта. Не передавайте пароль через чат или Git.

Администратор входит на `/login` и `/admin/` одной почтой и паролем. В админке
он может создать отдельную учётную запись кассира: почта, телефон, пароль, флаг «Персонал»;
«Суперпользователь» кассиру не нужен. `DEMO_MEMBERS=1` запускает `demo_members --no-staff`
при каждой Production сборке и добавляет только тестовых участников, без кассира.

## VPS

Технический адрес: `https://b5971f2535c5.vps.myjino.ru/`. Исходники на сервере —
`/opt/kokoklub`, Git-ветка `main`. Секреты находятся в `/opt/kokoklub/.env`, база — в
Docker volume `kokoklub_pgdata`, загруженные фото — в `backend/media/`; в Git их нет.

После отправки изменений в `main` обновление на VPS:

```bash
ssh -J vpn -p 49294 root@b5971f2535c5.vps.myjino.ru
cd /opt/kokoklub
bash deploy/update.sh
```

Скрипт делает `git pull`, собирает frontend в Node-контейнере, обновляет Django и Nginx.
Администратор создаётся отдельно. Его почту можно назначить существующей учётной записи
через Django shell; пароль при этом остаётся прежним.
