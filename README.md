# Клуб Коко

Сайт клуба объединяет афишу, бронирование, карту и счёт участника, общение и рабочее место стойки. Главная страница использует исходный дизайн из `frontend/demo`. Посетитель, резидент и сотрудник работают с одной базой Django.

Заказы, внесённые сотрудниками в клубном интерфейсе, можно оценить в кабинете. Для внешнего меню «Падачи» предусмотрен адрес `MENU_URL`. Оплату на внешней кассе сотрудник подтверждает в клубной системе вручную.

## Стек

Django 5 + DRF + SimpleJWT, PostgreSQL; React 18 + Vite + TypeScript.

- `backend/members` — участник (он же учётная запись), анкета, вход по почте и паролю
- `backend/club` — клубные карты, визиты, кабинет персонала
- `backend/chat` — личные переписки (пока без онлайна: новое видно при обновлении)
- `frontend/src/pages` — портал; `frontend/src/pages/staff` — экраны персонала

## Как гость становится членом клуба

1. На стойке QR-код на портал. Гость регистрируется с почтой, телефоном и паролем, заполняет анкету
   с согласием на обработку персональных данных.
2. Бариста пробивает в Падаче «Клубная карта — 1 500 ₽».
3. «Персонал → Привязать карту»: найти гостя по телефону или имени, считать метку телефоном
   либо USB-ридером и подтвердить привязку. Кнопка «Выдать карту» в списке гостей ведёт туда же.
4. После сохранения анкеты профиль появляется в картотеке. NFC-карта используется для визитов, поиска гостя персоналом и пополнения счёта; сообщения по-прежнему доступны владельцам клубной карты.

Гостя без смартфона бариста заводит сам («+ Новый гость»), после чего открывается страница
привязки карты. Для входа в такую учётную запись администратор позднее задаёт почту и пароль.
Потерянная карта — «Перевыпустить»: старая перестаёт работать, профиль и
переписки остаются. Если метка уже привязана к другому гостю, сервер отклоняет привязку.

## Разделы и доступ

- Гости видят только афишу (`/`) и регистрацию/вход (`/login`).
- После входа главная (`/`) показывает блоки картотеки и проектов с карточками, профиль и счёт участника. Полные разделы доступны по `/people`, `/projects` и `/me`; афиша — по `/afisha`. API картотеки и проектов также требует авторизации.
- Заполненная анкета с согласием появляется в картотеке без ожидания выдачи карты. Скрытые и неактивные профили не публикуются.
- Проекты добавляются и редактируются в анкете, отображаются в профиле автора и в общем разделе карточками.
- События афиши создаются в Django-админке: раздел «Афиша», дата/время и флаг «Опубликовано». Показываются опубликованные предстоящие события.

### Клубный счёт и пополнение на кассе

Клиент видит баланс и историю операций в личном кабинете. Пока страница открыта и видна, счёт обновляется каждые 10 секунд. Для пополнения клиент оплачивает нужную сумму на кассе клуба. После настройки терминала в кабинете также доступна онлайн-покупка токенов через Т-Банк.

Сотрудник открывает «Персонал → Гости и карты», считывает NFC телефоном или USB-ридером и попадает в карточку гостя. Нажимает «Пополнить счёт», вводит точную сумму, подтверждает получение оплаты на кассе и зачисление. Без NFC гостя можно найти по имени или телефону.

Каждое зачисление хранит сумму, клиента, сотрудника и дату. Если после подтверждения пропала связь, вернитесь в карточку гостя в том же браузере под той же учётной записью и нажмите «Продолжить пополнение». Повтор подтверждения не создаст второго зачисления. Обычный пользователь не может менять баланс; записи пополнений в админке доступны только для просмотра. Баланс учитывает пополнения, оплату собственного места резидента и возвраты за отменённую бронь. Для открытия брони задайте событию число мест для резидентов и цену в токенах. Эти места выделяются отдельно от гостевых пригласительных. Цена фиксируется в момент бронирования. При отмене больше чем за 24 часа до начала токены возвращаются на счёт.

Перед обновлением приложения примените миграции: `python manage.py migrate` из `backend/`.

## NFC

Карты — NTAG213-совместимые, 7-байтный UID (например, `53:FB:51:19:23:00:01`).
Идентификатор карты — заводской серийный номер, на карту ничего не пишется.
В базе хранится как `53FB5119230001`.

Ридер: USB, 13,56 МГц, **режим эмуляции клавиатуры, вывод UID в HEX, поддержка 7-байтного UID**.
Он «печатает» номер и Enter; экраны персонала ловят это сами (`useCardReader.ts`), фокус не нужен.

- «Экран у входа» (`/staff/entrance`) — планшет с USB-ридером у двери: приложил — вошёл,
  ещё раз — вышел. При переходе по ссылке «Экран у входа» на телефоне считывание NFC запускается
  тем же нажатием; при прямом открытии URL нужно нажать «Считать метку телефоном». Метка открывает карточку гостя
  без отметки входа. Содержимое метки, включая URL,
  не используется: сайт ищет гостя по серийному номеру метки (UID).
- «Кто в клубе» (`/staff`) — планшет на баре; ридер сюда тоже можно подключить.
- «Гости и карты» (`/staff/guests`) — на телефоне кассира кнопка «Посмотреть гостя по NFC».
  После касания метки открывается карточка гостя с фото, именем, телефоном и состоянием карты.
  Эта проверка не отмечает вход или выход. Сайт должен быть открыт по HTTPS в Chrome на Android,
  NFC на телефоне включён, а метка совместима с NDEF. Доступ к NFC выдаётся браузеру после
  нажатия кнопки. На iPhone и в неподдерживаемых браузерах используйте поиск по имени или
  телефону либо внешний ридер. Перед закупкой партии проверьте реальные метки: телефон должен
  передавать тот же UID, который сохранён при выдаче карты.
- «Привязать карту» (`/staff/bind`) — отдельная страница выдачи метки гостю. После выбора
  гостя кассир считывает UID телефоном или USB-ридером, сверяет его и подтверждает привязку.
- Кто забыл приложить карту на выходе, перестаёт числиться в клубе в `CLUB_DAY_START_HOUR` (6:00).

## Запуск

```bash
cp .env.example .env
docker compose up
docker compose exec backend python manage.py createsuperuser   # телефон, почта и пароль
docker compose exec backend python manage.py demo_members      # тестовые участники и учётка персонала (только для разработки)
```

Портал — http://localhost:5180, единый вход для участников и персонала — http://localhost:5180/login,
админка — http://localhost:5180/admin/ (та же почта и пароль).

Без Docker (SQLite):

```bash
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
DB_ENGINE=sqlite .venv/bin/python manage.py migrate
DB_ENGINE=sqlite .venv/bin/python manage.py runserver 8001
cd frontend && npm install && npm run dev:portal
```

Тесты: `DB_ENGINE=sqlite .venv/bin/python manage.py test` из `backend/`.

## Показать сайт по ссылке (GitHub Codespaces)

На GitHub: **Code → Codespaces → Create codespace on main**. Первый запуск — 3–5 минут:
ставятся зависимости, создаётся база SQLite с тестовыми участниками (`.devcontainer/`).
Потом портал откроется сам; адрес вида `https://<имя>-5180.app.github.dev`.

- Чтобы ссылка открывалась у других без входа в GitHub: вкладка **Ports** → порт 5180 →
  правый клик → **Port Visibility → Public**.
- Тестовые участники `79000000000`…`79000000005` созданы без доступа к входу.
- Персонал — http://…/login, `staff-demo@example.com` / `koko-demo-staff` (только локально).
- Codespace засыпает через ~30 минут без активности; после пробуждения портал поднимается сам.
  Это демо, не прод: данные тестовые, пароль персонала общий.

## Первый администратор на Vercel

В Production окружении Vercel добавьте `BOOTSTRAP_ADMIN_EMAIL` (ваша почта), `BOOTSTRAP_ADMIN_PHONE` (ваш мобильный номер)
и `BOOTSTRAP_ADMIN_PASSWORD` (новый длинный пароль) в **Project → Settings → Environment Variables**.
Затем сделайте **Deployments → Redeploy** последнего Production deployment. При сборке
`vercel.json` выполнит миграции и `bootstrap_admin`: он создаст администратора, если
этого номера ещё нет в базе. Повторные сборки не меняют его пароль и права. После успешного
входа удалите эти переменные и снова разверните сайт, чтобы пароль больше не оставался
в окружении проекта. Не передавайте пароль через чат или Git.

Администратор входит на `/login` и `/admin/` одной почтой и паролем. В админке
он может создать отдельную учётную запись кассира: почта, телефон, пароль, флаг «Персонал»;
«Суперпользователь» кассиру не нужен. `DEMO_MEMBERS=1` запускает `demo_members --no-staff`
при каждой Production сборке и добавляет только тестовых участников, без кассира.

## Основной интерфейс клуба

Для разработки запустите Django и выполните `npm run dev` в каталоге `frontend`. Vite проксирует запросы к Django по адресу `http://localhost:8001`; другой адрес задаётся через `VITE_API_PROXY`. Команда `npm run build` собирает основной сайт в `frontend/dist`. Путь `/portal/` сохранён для прежних ссылок. Все операции основного сайта доступны на главном домене через меню соответствующей роли.

[Карта экранов, серверных операций и сценариев проверки](docs/original-interface.md)

В админке у события отдельно задаются квоты для резидентов, гостей и приглашённых. Гостевой вход по коду организатора — 500 до 13:00 или 750 после, плюс указанная доплата за программу. Для серии при создании события выберите до 12 недель. При переносе измените дату той же записи. Действие отмены до начала возвращает токены, визиты и пригласительные по активным броням. Заявки отображаются в «Заявках на встречи». Команда может открыть сбор интереса и связать заявку с опубликованным событием. Запись на событие выполняется отдельно.

В карточке участника на стойке доступны оплаченные места на сегодня и вход организатора. После прихода организатору доступны 1 000 кредитов на еду; после отметки проведения — пригласительный и личный вход. Заказ еды расходует только целевые кредиты. Пакеты визитов сотрудники настраивают в админке. При покупке портал показывает количество, цену и срок действия до конца текущей карты.

### Онлайн-покупка токенов через Т-Банк

Укажите серверные переменные из `.env.example`. `TBANK_PUBLIC_ORIGIN` — публичный HTTPS-адрес портала. Для штатной сборки путь возврата — `/#cabinet`, для самостоятельной сборки `build:portal` — `/me`. Окружение банка выбирает `TBANK_TEST`. Тестовое подключение предназначено для отдельной базы. Параметры чека задаются по настройкам кассы клуба.

Сумма передаётся банку в копейках, на клубный счёт начисляется один токен за рубль. Банк отправляет уведомления на `/api/payments/tbank/notify/`. Зачисление происходит один раз после проверки подписи, номера заказа, идентификатора и суммы подтверждённого платежа. Заказы и уведомления о возврате для ручной сверки видны в «Онлайн-пополнениях». Настройку реального терминала и приём уведомлений из сети банка проверяют в тестовом окружении перед открытием платежей.

Если гостевой вход уже зачтён в оплаченный тариф, админка при отмене встречи укажет на необходимость сверки на кассе. Так сохраняется связь между уплаченным входом, фактическим визитом и доплатой за карту.

В афише резидент может оплатить место токенами или визитом из пакета и добавить гостя по включённому пригласительному одной операцией. Дополнительное гостевое место можно оплатить отдельно. Вход без брони отмечается на стойке по цене 500 токенов до 13:00 и 750 позднее, либо за один визит на соответствующем тарифе. Повторный вход в тот же день учитывается без нового списания.
